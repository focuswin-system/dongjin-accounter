## 뿌리 넷 — 개별 증상보다 이것부터

### 뿌리 1. 손익 판정 규칙이 여러 곳에 흩어져 있다

같은 사고가 **세 번째** 반복되고 있다.

| 언제 | 무엇이 사라졌나 | 어떻게 됐나 |
|---|---|---|
| 과거 | 청구서 정산 입금이 월별 현황에서 | `Docs.jsx:1556` — "2억이 넘게 들어왔는데 총 입금이 0원" → **프런트에서** 고침 |
| 지금 | 청구서 정산이 경영 도우미 매출·매입에서 | `analytics.js:85` — 같은 규칙이 여기엔 안 감 |
| 지금 | 어음으로 산 비용이 손익·분석에서 | 결제 후 계정이 `2102`라 자산·부채 제외에 걸림 |

`settleAcctCode()`가 붙이는 `1204 외상매출금` / `2101 외상매입금`은 자산·부채라
`pnlOnly()`가 걸러낸다. **이 앱은 미수금의 유일한 소스가 청구서다** — 즉 청구서를
쓰는 회사에서 경영 도우미의 매출은 "청구서를 안 거친 직접 입력분"만 센다.

→ **`lib/pnl.js`에 집계 범위 함수를 하나 만들고**(손익 계정 **또는** 청구서 정산
   **또는** 어음 결제), `analytics.js` · `transactions.js`의 `is_pnl` SQL ·
   `Docs.jsx`의 `useLedger`가 전부 그것만 쓰게 한다.
   지금은 그 escape 규칙이 프런트에만 살아 있고 정작 `pnl.js`에는 없다.

### 뿌리 2. 감사 규칙 누락이 반복된다 — 문지기가 DELETE만 본다

`check-isolation.js:454`가 `router.delete`만 훑는다. 그래서 **돈을 만들거나 지우는
POST/PATCH**는 문지기를 그냥 통과한다. 지금까지 사람 손으로 하나씩 채워 왔다
(대여금 → 정기 → 어음 → …).

빠져 있는 것:

| 경로 | 하는 일 |
|---|---|
| `/api/tax` **전체** | 세금 납부 거래 생성·삭제. `LEDGER_PREFIXES`에도 없어 **검사조차 안 됨** |
| `POST /transactions/transfer` | 이체 두 줄 생성 |
| `PATCH /transactions/:id/status` | '대기 → 완료'로 뒤집어 통장에서 돈이 나간 것으로 |
| `POST /finance/loans/:id/repay-adhoc` | 상환 거래 2건 (`/repay$` 정규식에 `-adhoc`이 안 걸림) |
| `POST /finance/investments/:id/redeem` | 원금+처분손익 2건 |
| `POST /lendings/:id/collect`, `/collect-adhoc` | 원금+이자 2건 |
| `POST /purchase-reqs/:id/issue-payable` | 미지급금 청구서 생성 |

→ **문지기가 POST/PATCH도 보게 한다**(장부 프리픽스에 한해). 그러면 다음 누락이
   사람 기억이 아니라 검사에서 걸린다.
→ `auditMap.js` `POST /notes`의 `target: 0`은 경로 전체가 대상 id로 들어간다 →
   `target: 'created'`.

### 뿌리 3. 실패를 조용히 삼켜 "데이터 없음"으로 보인다

`api.js:84` `notifyInfra`가 `network`/`ratelimit`/`5xx`만 알린다. **GET의 403·404는
토스트 없이 `[]`로 삼켜진다.** 여기에 화면 25곳이 `useState([])`로 시작해 fetch 전에
빈 상태를 그린다(`<Loading>`을 쓰는 화면은 10곳뿐).

가장 나쁜 셋:
- `Finance.jsx:1135` — 로딩 중 KPI를 **`0원` / `진행 중 0건`**으로 그림 (거짓 숫자)
- `Portal.jsx:17` — `.catch(()=>{})` → 홈 첫 화면이 "처리할 일이 없어요". 서버가 죽어도 같음
- `CashPanel.jsx:84` — 홈 자금 패널이 **흔적 없이 사라짐**

→ **`notifyInfra`에 GET 4xx를 추가**하고 `Portal`·`CashPanel`의 빈 catch를 없애면
   화면 25곳을 손대지 않고 착시가 사라진다.

## P1 — 오작동하거나 업무가 막힌다

### 장부·세무 신뢰성
- **전표 목록(분개장)에 청구서 발행 전표가 통째로 없다** — `voucherBook.js:27`. 세무사에게
  넘기는 엑셀에 매출 계정이 한 줄도 없다. 일계표는 세는데 분개장만 안 세어 두 장부가 다른 말을 한다.
- **부가세 숫자가 세 곳에서 다르다** — 세무관리 화면은 카드·현금 매입세액을 세는데
  (`tax.js:78`), **보고서와 엑셀은 invoices만 본다**(`invoices.js:177`·`reports.js:112`).
  안 고쳐진 쪽이 하필 **홈택스에 옮겨 적는 문서**다.
- **부가세 신고 자료 보고서에 연도 선택이 없다** — `Docs.jsx:2429`. 4분기 확정신고는
  다음해 1월인데 그때 Q4를 고르면 자료 없는 올해 10~12월이 나온다.
- **기타세액(원천세)이 자금 예측 어디에도 없다** — `other_taxes`에 납부 예정일 칸이 없다.

### 권한·안전

  다른 경로는 전부 `role === 'admin'`으로 가리는데 여기만 뚫림. 인건비는 가리면서 계좌만.
- **결의서 처리 취소가 '등록' 권한으로 통과** — `apiPerms.js`. 실제로는 거래를 DELETE 한다.

  대여금 등록은 서버 가드도 없어 **더블클릭 = 대여 2건 + 출금 2건**.
- **급여 지급 취소에 확인창이 없다** — `PayrollPayDrawer.jsx:115`. 클릭 한 번에 출금 거래 삭제.

### 데이터 연결이 끊기는 곳
- 직접 작성한 결의서로 만든 지출에 **거래처가 안 붙는다** — `Docs.jsx:354` (`vendor_id` 미전송)

기록해 둔다 — 다음에 같은 것을 다시 의심하지 않도록.

- 네이티브 `confirm`/`alert` 0건 · 원시 `<select>` 0건 · UI 문구의 '매칭' 0건 ·
  날짜 기본값 UTC 버그 0건 · `PageHeader` 27/29 · 인쇄 화이트리스트 **누락 없음**
