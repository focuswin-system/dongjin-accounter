# 3단계 — 입출금 재편 설계

계획: `01-plan/features/simplify-2026h2.plan.md` · 앞 단계: `repeat-templates.design.md`(2단계)

## 사용자 구상 (2026-09-15)

> 손에 든 것으로 고른다.

| 방향 | 방법 |
|---|---|
| 입금 | 입금전표 · 세금계산서 발행 → 입금 처리 · 반복거래에서 가져오기 |
| 출금 | 품의서/결의서 → 출금 처리 · 출금전표 · 세금계산서 수취 → 출금 처리 · 반복거래에서 가져오기 |
| 대체 | 대체전표 (돈이 안 움직임 — 입금·출금 밖에 둔다) |

입출금 메뉴는 **반복거래 / 세금계산서 / 입출금(거래내역+등록) / 카드대금 / 내부이체 / 급여·임금** 여섯.
같은 거래처·내용이 되풀이되면 "반복거래에 추가할까요?"를 제안한다.

## 지금 상태 (코드 실측 2026-09-18)

입출금 아래 잎이 아홉이고, **돈을 적는 입구가 다섯 화면에 흩어져 있다.**

| 잎 | 화면 | 하는 일 |
|---|---|---|
| 반복거래 `recurring_invoice` | Repeat.jsx | 2단계에서 정리됨 |
| 수시 입금 `billing_issued` | Billing.jsx(발행) | 매출 청구서 + 입금 처리 + "받은 서류" 선택창 |
| 수시 출금 `billing_received` | Billing.jsx(수취) | 매입 청구서 + 출금 처리 + "받은 서류" 선택창 |
| 경비 처리 `misc_pl` | MiscPL.jsx(116줄) | **주문 없는 거래만 거른 거래내역 + 등록 버튼** |
| 카드 대금 · 내부 이체 · 급여·임금 | 각자 | 그대로 둔다 |
| 거래내역 `ledger` | Ledger.jsx | 조회 전용 — **대체전표를 안 보여준다** |
| 전표 입력 `voucher_entry` | VoucherEntry.jsx | 대체전표(journal_vouchers) 등록 |

- 등록 입구는 "받은 서류가 뭔가요?"(DocTypeChooser)를 먼저 묻고 폼을 가른다. 수시 입금·수시 출금 두 화면에 같은 질문이 따로 있다.
- 거래 폼(Form.jsx)은 이미 거래처·금액을 넣으면 **미수 청구서 · 중복 · 이번 달 반복거래**를 알려준다(entry-hints). 구상의 "거래처 고르면 할 일이 뜬다"는 절반은 이미 있다.
- ⚠ **청구서 권한 구멍** — `/api/invoices` 는 네 자원(`billing_issued`·`billing_received`·`ar`·`ap`) OR 게이트이고 라우트 안에서 방향을 다시 안 본다.
  수시 출금 권한만 가진 역할이 매출 청구서를 조회·발행할 수 있다. 2단계 반복거래에서 실측으로 확인한 것과 같은 모양이다(그쪽은 고쳤다).

## 확정 (2026-09-18 사용자 답)

- "받은 서류" 선택창 — **없앤다.** 메뉴가 그 질문을 대신한다(출금 폼 머리 한 줄 링크만 남김).
- 반복 제안 — **3개월 중 2번**, 금액·날짜 안 봄, '안 할래요'면 그 거래처는 다시 안 물음.
- (2단계에서 넘어온 것) 매입 계약이 만든 출금 반복거래의 비목 — **반복거래에서 채운다**(계약 폼은 그대로).

## 결정

### 1. 메뉴 — 아홉 → 여섯

```
입출금
  반복거래     recurring_invoice                        (그대로)
  세금계산서   billing_issued      발행 · 수취 탭          ← 수시 입금 + 수시 출금
  입출금       ledger              거래내역 + [입금][출금][대체]  ← 거래내역 + 경비 처리 + 전표 입력
  카드 대금    card_payment                             (그대로)
  내부 이체    transfer                                 (그대로)
  급여·임금    hr                                       (그대로)
```

**잎 id 는 안 바꾼다**(권한 자원·바로가기·주소의 이름 — IA 재편 2차의 규칙). 흡수된 잎은 숨김 잎으로 남아 옛 주소로 들어오면 그 자리로 연다:
`billing_received` → 세금계산서의 수취 탭, `misc_pl` → 입출금의 '주문 없는 출금' 필터, `misc_income` → '주문 없는 입금', `voucher_entry` → 입출금 + 대체 폼.

### 2. 입구 = 손에 든 것 — 메뉴가 "받은 서류"를 대신 묻는다

| 손에 든 것 | 어디서 | 생기는 것 |
|---|---|---|
| 세금계산서를 발행 | 세금계산서 › 발행 | 매출 청구서(미수금) → 입금 처리 |
| 세금계산서를 받음 | 세금계산서 › 수취 | 매입 청구서(미지급금) → 출금 처리 |
| 승인된 결의서 | 문서업무 › 지급결의서 | 출금 처리(docExec, 그대로) |
| 영수증·카드전표·통장만 | 입출금 › [출금] | 출금전표(거래) |
| 통장 입금만 | 입출금 › [입금] | 입금전표(거래) |
| 돈이 안 움직임 | 입출금 › [대체] | 대체전표 |
| 매달 같은 돈 | 반복거래 | 청구서 또는 거래 |

**"받은 서류" 선택창(DocTypeChooser)을 없앤다.** 메뉴가 이미 그 질문이다 — 세금계산서 화면에서 여는 폼은 늘 청구서 폼, 입출금에서 여는 폼은 늘 전표다.
선택창이 막던 실수("세금계산서를 받았는데 경비로 적는다")는 출금 폼 머리에 한 줄로 남긴다: *세금계산서를 받으셨으면 세금계산서 › 수취에서 등록하세요* (링크).

### 3. 입출금 화면 — 거래내역 + 등록

- 등록 버튼 셋: **[입금] [출금] [대체]**. 입금·출금은 지금의 거래 폼(Form.jsx), 대체는 지금의 전표 입력 폼을 서랍으로.
- 목록에 **대체전표도 보인다**(구분 '대체'). 지금은 전표 입력 화면에 따로 있어 거래내역만 보면 빠진다.
- 필터 칩: 전체 · 입금 · 출금 · 대체 · **주문 없는 돈**(= 옛 경비 처리·잡손익. 조건은 MiscPL 과 같게 — 근거 주문·원가 주문 둘 다 비어 있음).
- 거래처를 고르면 폼이 알려주는 것(이미 있는 entry-hints 를 그대로 쓴다): 미수·미지급 청구서, 같은 돈 중복, 이번 달 반복거래.

### 4. 세금계산서 화면 — 발행 · 수취 한 화면

- 탭 둘. 탭 안은 지금 Billing.jsx 그대로(목록·입금/출금 처리·어음·홈택스 임포트).
- 등록 버튼은 탭에 따라 매출/매입 **청구서 폼을 바로 연다**(선택창 없음).
- 옛 '발행 없이 입금만 받아요'·'카드전표' 선택지는 입출금으로 갔다 — 탭 머리에 한 줄 링크.

### 5. 권한 — 청구서도 방향마다 따진다

세금계산서 한 잎에 두 탭이 들어오므로 탭마다 자원이 다르다:
발행 = `billing_issued` 또는 `ar`, 수취 = `billing_received` 또는 `ap`.

- 화면: 권한 있는 탭만 보인다. 둘 다 있으면 둘 다.
- 서버 `/api/invoices`: 반복거래와 같게 **줄의 kind 로 자원을 다시 따진다**(조회는 거르고, 쓰기는 403). 역할 미배정 계정은 perm.js 결정대로 통과.
- 입출금 잎은 `ledger`·`misc_pl`·`misc_income`·`voucher_entry` 중 하나라도 있으면 열린다. [대체] 버튼은 `voucher_entry` 가 있을 때만.

### 6. 반복 제안

입금·출금전표를 저장한 뒤, **같은 거래처 · 같은 방향 · 같은 비목(출금)** 이 지난 3개월 중 2개월 이상 있고
그 거래처·방향의 반복거래가 없으면 → 저장 토스트에 **[반복거래로 등록]**. 누르면 반복거래 등록 서랍을 그 값(거래처·비목·금액·일자·계좌)으로 채워 연다.
- 한 번 "안 할래요"를 누르면 그 거래처·방향은 다시 묻지 않는다(브라우저에만 기억 — 권유이지 규칙이 아니다).
- 금액은 판정에 안 쓴다(변동 공과금도 반복이다). 날짜도 안 쓴다(25일·27일은 같은 반복).

## 안 하는 것

- 거래 폼을 새로 짜지 않는다. Form.jsx 의 입금·출금 폼, VoucherEntry 의 대체 폼을 그대로 서랍으로 연다 — 3단계는 **입구와 목록**을 합치는 일이다.
- 카드 대금·내부 이체·급여는 안 합친다(IA 재편 2차에서 이유 기록 — 화면 뼈대가 다르다).
- 품의·결의서 복사는 3b.

## 복잡도 점검

- 줄어드는 것: 메뉴 잎 9 → 6, 등록 입구의 선택창 2개, 경비 처리 화면 1개, 전표 입력 화면 1개.
  "돈 나간 거 어디 적지?"의 답이 **세금계산서 있으면 세금계산서, 없으면 입출금** 하나가 된다.
- 새로 생기는 것: 입출금 목록의 '대체' 줄, 반복 제안 버튼.
- 남는 가드: 중복·미수 청구서·반복거래 힌트(entry-hints), 마감, 반복거래 이중 계상.

## 시나리오

1. 메뉴가 여섯이고, 옛 잎 주소(수시 출금·경비 처리·전표 입력)로 들어오면 새 자리의 맞는 탭·필터로 열린다.
2. 세금계산서 › 발행에서 등록 → 곧바로 매출 청구서 폼. 수취도 같다.
3. 입출금 › [출금] → 거래처를 고르면 미지급 청구서·반복거래 힌트. 머리에 "세금계산서 받으셨으면" 링크.
4. 입출금 › [대체] → 대체전표 저장 → 목록에 '대체'로 보인다. 필터 '대체'로 걸러진다.
5. '주문 없는 돈' 필터 결과가 옛 경비 처리 화면과 같다.
6. 같은 거래처 출금을 3개월 중 2번 적으면 제안이 뜨고, 누르면 반복거래 서랍이 채워져 열린다. '안 할래요' 뒤엔 안 뜬다.
7. 권한: 수시 출금 권한만 가진 역할 — 세금계산서엔 수취 탭만, `/api/invoices?kind=issued` 는 빈 목록, 매출 청구서 발행 403.
8. 인쇄·다크 모드: 새 화면에 인쇄 대상 없음(목록만). 다크에서 칩·힌트 색은 토큰만.

## 구현 메모 (2026-09-18)

- **잎 라벨은 '거래내역'으로 뒀다.** 구상은 '입출금'이었지만 도메인 이름과 같아 사이드바·크럼이
  '입출금 › 입출금'으로 두 겹이 된다. 등록 버튼(입금·출금·대체)은 화면 머리에 크게 세웠다. 바꾸려면 nav.js 라벨 한 곳.
- 흡수 관계는 `nav.js LEAF_ABSORBS` 한 곳 — 사이드바·라우트 가드(`perms.js can`)가 **들어가는 권한만** 이어 받는다.
  2단계 반복거래도 같은 구멍(출금 반복 권한만 있으면 메뉴에서 사라짐)이 있어 함께 넣었다.
- 방향별 줄 단위 권한은 `server/platform/sidePerms.js` 하나 — 반복거래·청구서가 같이 쓴다.
- 대체전표 입력은 `VoucherEntry.jsx` 의 `JournalEntryDrawer`(옛 화면을 서랍으로). 거래내역이 대체전표를 '대체' 줄로 함께 보인다.
- '주문 없는 돈' 판정은 `lib/txnScope.js isMiscPl`(옛 MiscPL 화면 조건 그대로). MiscPL.jsx·DocTypeChooser.jsx 는 지웠다.
- 반복 제안: 서버 `lib/repeat.js repeatSuggestion` + `GET /api/repeat-templates/suggest`, 화면은 토스트에 버튼(ui.jsx `actions`).

## 검증 기록 (2026-09-18, 로컬 `repeat` 테넌트)

1. 메뉴 여섯(반복거래·세금계산서·거래내역·카드 대금·내부 이체·급여·임금). 옛 주소 `#billing_received`→수취 탭,
   `#misc_pl`→'주문 없는 돈' 필터, `#voucher_entry`→대체 서랍. 사이드바는 새 잎이 켜진다.
2. 세금계산서 › 발행에서 등록 → 곧바로 청구서 폼(제목도 '세금계산서 발행'). 수취도 같다.
3. 거래내역 [출금] → 폼 머리에 '세금계산서를 받으셨으면 → 수취' 링크.
4. [대체] → 대체전표 저장 → 목록에 '대체'(칩 건수 포함), 줄을 누르면 전표 + 삭제, 삭제 후 사라짐.
5. '주문 없는 돈' — 옛 경비 처리와 같은 조건.
6. 같은 거래처 출금을 8·9월에 적으면 저장 뒤 토스트 [안 할래요][반복거래로 등록] → 반복거래 등록 서랍이 채워져 열린다
   (출금·바로 출금·거래처·비목·금액·부가세 포함·매월·계좌). 한 달뿐일 땐 안 뜬다.
7. 권한 — 매입(billing_received)만 가진 계정: 사이드바에 세금계산서만, 발행 주소로 와도 수취로 열림, 탭 줄 없음,
   거래내역 링크 숨김. API: 매출 목록 빈 배열, 매출 조회·발행·삭제·일괄·임포트 403, 매입은 200. 관리자는 그대로.
8. 다크 모드 — 발행·수취 탭·안내 줄·토스트 버튼이 토큰으로만 칠해져 대비 유지.

### 검증에서 고친 것
- **거래 폼이 거래처·계좌·비목 목록을 앱을 켤 때 한 번만 읽었다.** 폼이 App 에 늘 붙어 있어, 세션 중에 새로 만든
  거래처가 새로고침 전까지 '검색 결과가 없어요'로 떴다(기존 결함). 열 때마다 다시 읽는다.
- 전표 보기가 대체전표에도 "돈이 실제로 오간 시점의 전표예요"라고 적었다 — 대체전표용 문구를 따로 뒀다.
- 합계 카드 '지출 합계' ↔ 칩 '출금' 이름 어긋남, 버튼 순서(입금→출금), 반복 제안 문구("최근 3개월 중 2개월"),
  권한 없는 사람에게 보이던 막다른 링크(거래내역·세금계산서로 가는 길).
