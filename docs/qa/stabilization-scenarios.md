# 안정화 시나리오 설계 — 일반회계 · 인사급여

> 목적: 지금까지 구축한 **일반회계**(계약·청구·거래·정기반복·부가세)와 **인사급여**(근로/용역/일용 계약·급여대장·지급·명세)를 실사용 흐름대로 end-to-end 검증하고, 결함을 잡아 수정·재검증을 반복해 안정화한다.
> 실행 방식: 별도 세션에서 이 문서를 소스로 (1) 임시 풀스택 서버(PORT=3096~3099, **3001/운영 안 건드림**) 기동 → (2) API(Node http)로 데이터 흐름 검증 + Playwright로 UI 검증 → (3) 결함 발견 시 수정 → (4) 재검증. 각 시나리오 끝에 테스트 데이터 정리(`[검증]`/`[샘플]` prefix).
> 우선순위: **P0**(돈·데이터 정합성, 깨지면 치명) > P1(핵심 흐름) > P2(부가·edge).

---

## A. 인사급여 — 근로계약 & 급여대장

### A1 [P0] 직원 등록 → 급여대장 생성 → 명세 → 지급 → 미지급/과지급
1. 근로계약 화면에서 직원 등록(고용형태 정규직, 기본급 300만, 4대보험 자동). 사번 자동 채번.
2. 인사관리 → 급여대장 → 해당 월 생성. **기대**: 계약 pay_items 기준으로 명세 생성, 실수령 = 300만 − 공제.
3. 명세서 편집: 공제(4대보험·소득세)를 고지 금액으로 입력 → 저장. **기대**: 실수령 재계산.
4. 지급 등록(실지급액 = 실수령, 계좌 선택). **기대**: 거래내역에 '급여' 지출 자동 기록, 계좌잔액 감소, payStatus=지급완료.
5. 부분 지급 → **기대**: 미지급 = net−paid(양수). 초과 지급 → 과지급(음수).
- 검증축: 거래내역 반영 · 계좌잔액 · 요약 타일(미지급/과지급) · seq=0.

### A2 [P0] 연봉 인상 = 새 계약(이력 보존)
1. 기존 근로계약 상세 → '새 계약(연봉 인상)' → 기본급 상향.
2. **기대**: 기존 계약은 만료/이력에 남고 새 계약이 현재. 계약 이력 탭에 2건. 급여대장 생성은 **가장 최근 시작 계약** 기준.
- 함정: `/generate`의 "한 직원 최신 계약 1건" dedup, 유효기간 겹침.

### A3 [P0] 퇴사 처리
1. 상세 → 퇴사 처리(퇴사일 오늘=KST).
2. **기대**: 직원 status=퇴사·leave_date 기록, 진행 계약 만료. 이후 급여대장 생성 대상 제외. 기존 지급 거래는 보존.

### A4 [P1] 월 기준급여 표시 정합
- 목록 '월 기준급여' = `monthly_net`(pay_items 계산), 상세 = `computeItems(pay_items).net`. **급여대장 생성 전에도** 0이 아닌 계약 기준값이어야(리뷰 지적 수정분 회귀).

### A5 [P1] 급여대장 삭제/이 달 비우기
- 행 삭제·월 전체 삭제 시 연결 지출 거래는 남고 payroll_id만 해제.

## B. 인사급여 — 용역 · 일용

### B1 [P0] 인력 등록(고용형태 자동채움) → 단가표 → 지급(수량→금액) → 누적
1. 인력 등록: 고용형태=프리랜서(사업) 선택 → **기대**: 소득구분=사업, 단가 단위=건 자동. 단가표 2품목.
2. 상세 → 지급 등록: 수량 입력 → **기대**: 금액=수량×단가 자동, 원천징수 확정 입력 → 차인지급액.
3. '지금 지급' 체크 → **기대**: 거래내역 '용역비' 지출 자동, 3타일(누적 지급/발생/미지급), 업무별 누적.
4. seq: 같은 달 2회차 지급 → seq=1,2. **급여대장(근로)엔 안 섞임**(seq≥1 분리).

### B2 [P0] 일용 지급 + 상용전환 경고
1. 고용형태=일용(일반, conv=3) 인력, 계약 시작 4개월 전. 지급 몇 회.
2. **기대**: `/alerts/conversion`에 등장, 목록 '전환검토' 배지 + 상단 경고. 건설(conv=12)은 12개월 기준.
- 함정: conv_alert_months 계약별 저장(일용 기본 3), months 계산(start~최근 지급월).

### B3 [P1] 소득구분별 명세서 4종 인쇄
- 사업/일용/기타 = 공통 템플릿(지급·공제·차인지급액), 근로 = 법정 임금명세서. **금액이 0이 아니어야**(computeItems로 산출 — 리뷰 지적 회귀). 이름·업무명에 `<`,`&` 넣어도 레이아웃 안 깨짐(이스케이프).

### B4 [P1] 복제(이 계약으로 새로)
- 단가표·조건 복사, 새 계약 status=진행중, 지급 이력은 복사 안 됨.

### B5 [P2] 소득구분 필터 칩 / 인사관리 용역·일용 대장 탭
- income_type 필터, 월 이동, 요약 타일(지급 발생/완료/미지급/인원).

## D. 일반회계 — 매출/매입 계약 & 청구

### D1 [P0] 매출 총액형: 계약 → 청구 일정 자동 → 발행 → 입금 → 미수금
- 계약 저장 시 '일시' 청구 일정 자동 생성. 발행→미수금, 기입금 옵션, 정산→수금 거래.

### D2 [P0] 매출 정기형: 초기 일시금 + 주기 정액, 갱신/종료
- 정기청구 자동, 텀 총액 파생, 갱신 시 종료일·단가 반영. **소급 홍수 차단**(등록일=created_at부터, 736a236) + 미래 35일 미리보기.

### D3 [P0] 매출 기성형: 품목 단가표 → 기성 청구(수량×단가) → 품목별 누적 (df7cde6)
- 기성 청구 내역 탭, 3타일(누적 청구/수금/미수), 거래명세서.

### D4 [P0] 매입 계약: 청구 수취 → 지급 → 미지급금 → 지급결의서
- gubu A/E 판별, 지급결의서(품목별 from-invoice, 부가세 별도 라인), 지급→미지급금 감소.

### D5 [P1] 부가세: 과세/면세(vat_mode) — 면세 계약 청구 시 부가세 0.

### D6 [P1] 정기지출 자동생성 / 미래 회차 미리보기 / 미래 기입금 가드(KST) (736a236).

## F. 교차 정합성 (P0)

- **급여 지급 → 거래내역 → 계좌잔액** 3중 반영 일치.
- **seq=0(근로) vs seq≥1(용역)** 급여대장·요약·ReportTax4 분리.
- 계약/계약서/직원/지급 삭제 시 연결 해제(장부 보존, 고아 없음).
- 금액 콤마·정수 저장·BIGINT 범위.
- 날짜 전부 KST(localToday ↔ 서버 kstToday) 정렬.
- PWA SW 캐시: 검증 시 `?v=N` 또는 unregister.

## 실행 체크리스트(별도 세션)

1. 로컬 `.env`(winc_dj_ac) 비번이 로컬 MySQL과 불일치 → **root/1234 오버라이드** 임시서버(3096~3099). 3001/운영 금지.
2. 로그인 우회: `localStorage.loggedIn=1` + user. SW 캐시 시 `?v=N`.
3. 한글 API 테스트는 Bash curl이 UTF-8 깨뜨림 → **Node http 스크립트**.
4. 시나리오별 API 검증 → UI(Playwright) 검증 → 결함 수정 → 재검증. 데이터 정리(`[검증]` prefix).
5. 발견 결함은 심각도(P0~P2)로 분류, 수정 후 회귀. 배포는 사용자 확인 후 `bash deploy.sh`(+백업).
